# Revisión antes de entregar

## Producto y diseño

- La tarea principal del usuario es fácil de encontrar.
- Los cambios respetan el brief y el sistema de diseño.
- El contenido tiene una jerarquía clara y textos comprensibles.
- Las variantes, si se solicitaron, exploran decisiones sustanciales.
- Las referencias externas tienen enlaces y no se confunden con autoría propia.

## Interacción

- Las funciones existentes siguen disponibles.
- Búsqueda, filtros y cambios de vista producen resultados coherentes.
- Los estados de carga, vacío y error son entendibles.
- Los menús y diálogos funcionan con teclado y devuelven el foco cuando corresponde.
- La interfaz distingue datos de muestra, guardado local e integración real.

## Visual y responsive

- Revisar al menos una anchura de escritorio y una estrecha.
- Verificar que títulos, controles y menús no se corten ni se superpongan.
- Comprobar contraste, legibilidad y áreas táctiles.
- El movimiento respeta la preferencia de movimiento reducido.
- Registrar qué se comprobó realmente; una captura no verifica toda una interacción.
- Cuando el comportamiento táctil importa, indicar si falta probar en un dispositivo físico.

## Antes de subir cambios a esta colección

- Cada skill tiene `name` y `description` en su front matter.
- Los enlaces relativos apuntan a archivos existentes.
- No hay credenciales, correos privados, rutas personales ni contenido de clientes.
- Los cambios en una skill quedan reflejados en CHANGELOG.md.
- El material de terceros conserva su fuente y tiene permiso de redistribución antes de incluirse.
